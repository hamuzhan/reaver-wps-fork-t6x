# AGENTS.md

Reaver (`reaver-wps-fork-t6x`, v1.6.6): a C tool for brute-forcing WPS PINs. Builds
two programs (`reaver`, `wash`) from a single binary. Linux-only.

## Build / install

All build commands run from `src/`, NOT the repo root.

```
cd src
./configure        # optional: --enable-libnl3 | --enable-libnl-tiny | --enable-savetocurrent
make               # builds ./reaver; ./wash is a symlink to it
sudo make install  # installs reaver + wash to $prefix/bin
make clean
```

- There is **no `make distclean`** (docs/README is stale upstream prose; trust the Makefile: only `all`, `clean`, `install`).
- libnl flags are only needed when the kernel lacks wext support (most modern distros); otherwise channel-switching options silently no-op.
- Build requires `libpcap-dev`; links `-lm -lpcap -lpthread -lrt` (the `-lm -lpcap` come from `configure.ac`, not the Makefile) and uses Linux Wireless Extensions and `timer_settime`. It does **not** build natively on macOS — use a Linux box/VM/container to compile or test.

## Build-system layout (easy to get wrong)

- `Makefile` is hand-written, NOT generated — edit it directly.
- `configure` is autoconf-generated and committed. After editing `configure.ac`, regenerate it (`autoreconf -i` / `autoconf`) and commit the result (see git history: "regenerate configure script").
- `config.mak` is generated by `./configure` from `config.mak.in`.
- Bump the version in `src/VERSION` (also feeds `configure.ac`).

## Generated files — never edit or commit by hand

- Gitignored: `src/version.h` (from git tags / `VERSION` via `version.sh`), `src/config.h`, `src/config.mak`.
- `src/lwe/wireless.h` is also generated (copied from `lwe/wireless.<ver>.h` by `make`) but is **not** gitignored and **not** tracked — don't commit it. `make clean` deletes it plus `version.h`.

## Code map

- Entry point `main.c` dispatches by `argv[0]` basename: `reaver` -> `reaver_main` (`wpscrack.c`), `wash` -> `wash_main` (`wpsmon.c`).
- Reaver's own code = top-level `src/*.c` + `src/libwps/`. Core attack logic: `cracker.c`, `exchange.c`, `send.c`, `builder.c`, `80211.c`, `pins.c`, `keys.c`, `pixie.c`, `session.c`.
- **Vendored — do not hand-edit normally** (copied from wpa_supplicant): `common/`, `crypto/`, `tls/`, `utils/`, `wps/`. `lwe/` is Wireless Tools v29.
- Deep-dive architecture docs (attack flow, packet layer, crypto, pixie-dust, keyspace, wash) live in `docs/dev/` — start at `docs/dev/README.md`. The user-facing `docs/` (`README*`, `reaver.1`) is mostly stale upstream prose.

## Tests / CI

- No test suite and no CI. Verification = it compiles and links.
- `extest` is a manual-only dev target compiling `exchange.c` with `-DEX_TEST` (`make extest`).

## Conventions

- C, indent with **tabs**.
- Reaver-authored source files carry a GPLv2 header with an OpenSSL-linking exception; preserve it on files that have it.
- `tools/logfilter.py` is Python 3 (shebang `python3`), indented with **tabs** not spaces; it pipes wpa_supplicant/reaver debug logs into pixiewps.
